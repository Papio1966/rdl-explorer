# RDL-036.4 - Browser PostgreSQL Runtime Cutover

## Objective

Complete RDL-036 for the seven shared primary browse families by switching production browser authority from the committed JSON projections to the same-origin PostgreSQL runtime API established in RDL-036.2 and proven by RDL-036.3 dual read.

## Baseline

- merged baseline: `c8da2f399606580a44db899bf38aa32cd758a64b`
- RDL-036.1 proved exact PostgreSQL projection parity;
- RDL-036.2 established the generic source/release-scoped runtime API;
- RDL-036.3 proved JSON/API dual-read parity and fail-closed mismatch handling.

## Authority modes

`VITE_RDL_BROWSER_READ_MODE` supports three explicit modes:

- `api` - PostgreSQL runtime API is the shared-browse authority.
- `dual` - JSON and API are compared exactly; after parity, the API candidate is rendered.
- `json` - explicit rollback/reference mode using the committed JSON indexes.

If the variable is not configured:

- production builds default to `api`;
- Vite development and the existing GitHub browser harness default to `json`.

This distinction is intentional. The GitHub Playwright harness serves the browser with plain Vite and does not host the serverless PostgreSQL API. Production deployment does host the same-origin API. The deterministic local contract uses the real PostgreSQL runtime service to prove the API authority path.

## Shared-browse scope

The cutover applies only to the seven generic browse families:

1. Tag Classes
2. Equipment Classes
3. Document Types
4. Properties
5. Source Standards
6. Disciplines
7. Units of Measure

For each selected source/release/entity family, the browser requests:

- exact search projection records for `sourceKey + releaseKey + entityType`;
- exact same-type `entity_parent` relationships for hierarchy construction.

No browser database credentials are introduced.

## Fail-closed behavior

`api` mode never silently falls back to JSON. API unavailability, unexpected schema, source/release leakage, package drift during pagination, invalid page state, or hierarchy-scope leakage is an explicit browse error.

Operational rollback is an explicit configuration decision: set `VITE_RDL_BROWSER_READ_MODE=json` and rebuild/redeploy.

## Deferred cutovers

RDL-036.4 does not switch:

- global search;
- canonical entity detail;
- CIS Builder or derivation;
- Assistant retrieval;
- specialist diagnostics/lifecycle views.

Those consumers keep their existing contracts until separately converged.

## Invariants

- source + release + entity type + native identifier remains the canonical identity;
- explicit release selection is never replaced by latest;
- no CFIHOS fallback;
- hierarchy is built only from authoritative same-type `entity_parent` relationships;
- API paging remains bounded at 500 rows;
- committed JSON projections remain unchanged as rollback/reference oracles;
- no PostgreSQL schema migration;
- no API/server implementation change;
- no local Playwright requirement.

## Acceptance

RDL-036.4 passes when deterministic validation proves:

- production default resolves to `api` and development/CI default resolves to `json`;
- the shared browser no longer directly loads JSON indexes;
- API authority exactly equals the committed rollback oracle for all seven Water / Desalination browse families and representative CCUS browse;
- JSON rollback performs no API call;
- dual mode still compares exact parity and renders the API candidate;
- API failure fails closed without JSON substitution;
- updated RDL-034 and RDL-036.3 contracts remain green after their intentional runtime-boundary change;
- RDL-035, regression and production build remain green;
- runtime oracle hashes are unchanged.
