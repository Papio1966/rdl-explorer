# RDL-036.3 — Projection/API Dual Read

## Objective

Introduce a controlled browser-side dual-read stage between the committed JSON runtime projection and the PostgreSQL runtime API created in RDL-036.2.

RDL-036.3 does **not** make PostgreSQL authoritative for browser rendering. The JSON projection remains the returned/rendered data. In explicit `dual` mode, selected shared-browse reads are allowed to render only after the PostgreSQL API has produced an exact semantic match for the same source, release and entity family.

## Baseline

- merged baseline: `023269d593d505adbfd76de49b65441536a99d68`
- RDL-036.1 already proved exact PostgreSQL projection parity with the committed browser oracles;
- RDL-036.2 already proved the generic source/release-scoped runtime API;
- those accepted gates are not repeated unless their validated files change.

## Controlled browser modes

`VITE_RDL_BROWSER_READ_MODE` supports:

- `json` — safe default. Shared browse reads the committed JSON indexes only.
- `dual` — JSON is read first, then the matching PostgreSQL runtime API result is fetched and compared. JSON is rendered only when parity is exact.

Any other configured value fails explicitly.

The default remains `json` in RDL-036.3 because the current GitHub Playwright harness serves the application through plain Vite and does not host the serverless PostgreSQL API. RDL-036.4 will make the explicit authority/cutover decision.

## Dual-read scope

The shared release-aware browser compares only the data it actually needs for a selected browse family:

1. search projection records for exact `sourceKey + releaseKey + entityType`;
2. authoritative same-type `entity_parent` relationships for that entity family.

This avoids transferring the entire 80,832-row relationship oracle for every browse page. Pagination is bounded to the RDL-036.2 API maximum of 500 rows per request.

## Fail-closed rules

In `dual` mode the browser fails closed when:

- the runtime API is unavailable;
- the API response schema is unexpected;
- source/release scope differs;
- pagination totals or offsets change unexpectedly;
- search record counts/content differ;
- hierarchy relationship counts/content differ.

Mismatch messages are emitted to the browser console and propagate to the existing shared-browse error state. API results are never substituted silently for JSON results in this increment.

## Invariants

RDL-036.3 must preserve:

- source + release + entity type + native identifier identity;
- explicit release selection with no implicit latest substitution;
- no CFIHOS fallback;
- authoritative `entity_parent` hierarchy only;
- existing JSON global search and canonical detail runtime;
- no browser database credentials;
- no PostgreSQL schema migration;
- no CIS or Assistant cutover;
- no local Playwright requirement.

## Acceptance

RDL-036.3 passes when deterministic validation proves:

- default `json` mode performs no API call;
- `dual` mode compares real PostgreSQL runtime-service responses with the committed JSON browse oracle for representative Water / Desalination and CCUS families;
- a deliberately altered API row fails closed;
- an API failure fails closed;
- the shared browser still renders the JSON records after successful comparison;
- RDL-034/RDL-035 browser contracts remain green;
- regression and production build remain green;
- runtime index hashes are unchanged;
- the exact RDL-036.3 changed-file set is present.
