# RDL-034 — Unified Release-Aware Browse

## Product rule

**Source and release change the data, not the navigation paradigm.**

Release lifecycle status (`draft`, `candidate`, `reviewed`, etc.) is governance metadata. It must not decide whether users receive a hierarchy browser, card grid, or another navigation model.

## RDL-034.1 — Tag Class browse foundation

RDL-034.1 introduces a reusable release-aware browse shell for non-CFIHOS Tag Classes while leaving the proven CFIHOS Tag Classes browser unchanged.

The shared shell:

- is explicitly scoped by `sourceKey`, `releaseKey`, and `entityType`;
- loads entities from the release-aware search index;
- loads `entity_parent` relationships from the release-aware relationship index;
- renders the established two-panel search/hierarchy interaction;
- uses authoritative parent relationships when present;
- safely renders a flat vocabulary in the same shell when the source supplies no parent relationships;
- never imports a CFIHOS repository or CFIHOS entity type;
- opens canonical release-aware detail routes directly;
- does not branch on release status.

### Initial proof sources

- Water / Desalination 2.0 candidate
- CCUS 2.0 candidate

The word `candidate` has no UX-routing meaning in this implementation.

## Non-goals for RDL-034.1

- no CFIHOS browse replacement;
- no Equipment Class convergence yet;
- no Document / Discipline / Property browse convergence yet;
- no search-index or relationship-index regeneration;
- no identifier, package, or release semantic changes;
- no database changes.

## Validation

Local deterministic gates cover RDL-029 through RDL-034, regression, build, index stability, and diff checks. Browser E2E/accessibility is authoritative in GitHub Actions Chromium; local Playwright is intentionally not required.

## RDL-034.1A — Chromium compatibility and accessibility repair

GitHub Chromium identified two issues after the unified browse foundation was introduced:

- the pre-RDL-034 scope-isolation E2E still expected the retired generic-card source banner rather than the new shared browse shell;
- leaf hierarchy rows rendered a decorative dot inside a button with no accessible name, which Axe correctly reported as a critical `button-name` violation.

The repair updates the scope-isolation browser contract to assert explicit `data-source-key` / `data-release-key` identity and source-native search results, and renders leaf hierarchy affordances as inert `aria-hidden` spans. Expand/collapse controls remain real named buttons only when a node has children. No runtime index, release, hierarchy, identity or routing semantics change.

## RDL-034.2 — Equipment Class browse convergence

RDL-034.2 extends the shared release-aware browse shell to non-CFIHOS Equipment Classes. CFIHOS continues to use its existing specialist Equipment Class browser in this increment.

The source data provides complete single-root hierarchy coverage for the v2 candidate releases used as proof cases:

- Water / Desalination: 50 Equipment Classes and 49 authoritative `entity_parent` relationships;
- CCUS: 61 Equipment Classes and 60 authoritative `entity_parent` relationships.

The scope guard therefore delegates both `tag_class` and `equipment_class` to `RdlReleaseAwareBrowse` for non-CFIHOS sources. The shared shell remains explicitly source/release/type scoped, retains the RDL-034.1 accessibility repair for leaf nodes, and opens canonical release-aware entity detail routes directly.

The browser contract now exercises Water and CCUS for both Tag Classes and Equipment Classes. Release lifecycle labels remain provenance only and do not alter the navigation paradigm.

## RDL-034.3 — Non-hierarchical browse convergence

RDL-034.3 extends the same release-aware browse shell to non-CFIHOS Document Types and Properties. It proves that a common navigation paradigm does not require inventing hierarchy where the source does not provide one.

The v2 candidate proof releases contain:

- Water / Desalination: 28 Document Types and 63 Properties;
- CCUS: 42 Document Types and 96 Properties.

Neither source/release contains same-type `entity_parent` relationships for `document_type` or `property`. The shared browser therefore exposes those vocabularies in explicit flat mode inside the same two-panel shell used by hierarchical classes. The flat mode is deterministic and visible through `data-browse-mode="flat"`; Tag and Equipment Class releases with authoritative parents continue to expose `data-browse-mode="hierarchy"`.

The generic shell now owns entity-neutral presentation metadata rather than assuming every entity is a class. Document Types use the `Information` browse category and a document icon; Properties use the `Reference` category and a dictionary/reference icon. Search labels and singular empty-state labels are entity-appropriate.

Flat mode does not imply weak semantics. Document Types and Properties retain their release-aware relationships in canonical detail, including class-document, discipline, information-requirement, class-property, controlled-value, unit and source-standard relationships. RDL-034.3 changes only browse navigation.

CFIHOS Document Types and Data Dictionary continue to use their existing specialist browse pages in this increment. Runtime indexes, release identity, package identity, relationship generation and canonical detail rendering are unchanged.
