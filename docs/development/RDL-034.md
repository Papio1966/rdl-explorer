# RDL-034 — Unified Release-Aware Browse

## Product rule

**Source and release change the data, not the navigation paradigm.**

Release lifecycle status (`draft`, `candidate`, `reviewed`, etc.) is governance metadata. It must not decide whether users receive a hierarchy browser, card grid, or another navigation model.

## RDL-034.1 — Tag Class browse foundation

RDL-034.1 introduces a reusable release-aware browse shell for non-CFIHOS Tag Classes while leaving the proven CFIHOS Tag Classes browser unchanged.

The shared shell:

- is explicitly scoped by `sourceKey`, `releaseKey`, and `entityType`;
- loads entities from the release-aware search index;
- loads `entity_parent` relationships from the release-aware relationship index;
- renders the established two-panel search/hierarchy interaction;
- uses authoritative parent relationships when present;
- safely renders a flat vocabulary in the same shell when the source supplies no parent relationships;
- never imports a CFIHOS repository or CFIHOS entity type;
- opens canonical release-aware detail routes directly;
- does not branch on release status.

### Initial proof sources

- Water / Desalination 2.0 candidate
- CCUS 2.0 candidate

The word `candidate` has no UX-routing meaning in this implementation.

## Non-goals for RDL-034.1

- no CFIHOS browse replacement;
- no Equipment Class convergence yet;
- no Document / Discipline / Property browse convergence yet;
- no search-index or relationship-index regeneration;
- no identifier, package, or release semantic changes;
- no database changes.

## Validation

Local deterministic gates cover RDL-029 through RDL-034, regression, build, index stability, and diff checks. Browser E2E/accessibility is authoritative in GitHub Actions Chromium; local Playwright is intentionally not required.

## RDL-034.1A — Chromium compatibility and accessibility repair

GitHub Chromium identified two issues after the unified browse foundation was introduced:

- the pre-RDL-034 scope-isolation E2E still expected the retired generic-card source banner rather than the new shared browse shell;
- leaf hierarchy rows rendered a decorative dot inside a button with no accessible name, which Axe correctly reported as a critical `button-name` violation.

The repair updates the scope-isolation browser contract to assert explicit `data-source-key` / `data-release-key` identity and source-native search results, and renders leaf hierarchy affordances as inert `aria-hidden` spans. Expand/collapse controls remain real named buttons only when a node has children. No runtime index, release, hierarchy, identity or routing semantics change.
