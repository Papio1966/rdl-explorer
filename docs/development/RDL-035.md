# RDL-035 — CFIHOS Shared Browse Convergence

## RDL-035.1 — Readiness & Parity Audit

### Objective
Determine whether CFIHOS 2.0 can move from the seven retained specialist browse implementations onto `RdlReleaseAwareBrowse` without losing useful browse/search/filter capability.

### Decision
**Do not cut CFIHOS over yet.**

CFIHOS is structurally ready in the release-aware indexes, but six of the seven browse families still expose useful specialist metadata/search/filter behavior that is not represented in the generic `RdlSearchRecord` projection.

### Structural result
- Tag Classes: 848 records / 847 authoritative same-type parents / hierarchy
- Equipment Classes: 832 / 831 / hierarchy
- Document Types: 329 / 0 / flat
- Properties: 1,388 / 0 / flat
- Source Standards: 305 / 0 / flat
- Disciplines: 34 / 0 / flat
- Units of Measure: 1,472 / 0 / flat
- 1,678 same-type parent relationships; 0 endpoint-integrity failures

### Parity result
- Tag Classes: not ready — parent-name search, synonyms, abstract marker are not in generic browse projection
- Equipment Classes: not ready — parent-name search, existence reason, synonyms, abstract marker are not in generic browse projection
- Document Types: not ready — short code, classification and synonyms are not in generic browse projection
- Properties: not ready — datatype, UoM dimension, picklist, existence reason and synonyms are not in generic browse projection
- Source Standards: ready in principle — source-standard code is already the indexed record name and description is the definition
- Disciplines: not ready — discipline code is not in generic browse projection
- Units of Measure: not ready — symbol, UNECE code, dimension/system metadata, synonyms and dimension filtering are not in generic browse projection

### Architecture decision
RDL-035 must generalize the release-aware browse/search projection rather than re-introduce CFIHOS repository dependencies into `RdlReleaseAwareBrowse`.

## RDL-035.2 — Generic Browse Metadata Projection

### Objective
Add a source-neutral metadata projection to the existing release-aware search index so the shared browser can preserve richer engineering browse behavior before CFIHOS cutover.

### Architecture decision
Enrich `RdlSearchRecord` rather than creating a second browse-specific runtime index.

The existing generator already owns exact source/release/package identity and directly reads the authoritative workbooks. Keeping browse metadata in the same projection avoids duplicate runtime indexes, duplicate release identity and synchronization risk.

### Normalized optional metadata
`RdlSearchRecord` now supports:
- `aliases[]`
- `searchText[]`
- `secondaryLabel`
- `tertiaryLabel`
- `badges[]`
- `facets{}`

These are generic presentation/search concepts. `RdlReleaseAwareBrowse` contains no CFIHOS repository dependency and no source-key branch.

### Projected capability
- Tag Classes: parent search, aliases and Abstract badge
- Equipment Classes: parent/existence search, aliases and Abstract badge
- Document Types: short code, classification and aliases
- Properties: datatype, dimension/unit, picklist, existence reason and aliases where supplied by the source
- Source Standards: existing code/name/description representation retained
- Disciplines: discipline code
- Units of Measure: symbol, UNECE code, dimension/system metadata, aliases and generic `dimension` facet

### Generic facet behavior
Facet controls are generated only from authoritative projected facet metadata. The browser does not infer facets from names, codes or free text.

The first proof is Unit-of-Measure dimension filtering:
- CFIHOS preserves its authoritative dimension identity in the projection for later cutover.
- Water / Desalination and CCUS use the same generic facet contract immediately in their shared browse routes.
- the selected facet is represented in the URL query string using the facet key (`?dimension=...`).

### Runtime indexes
- `public/rdl-search-index.json` changes because its schema is intentionally enriched.
- `public/rdl-relationship-index.json` must remain byte-for-byte unchanged.
- record identities and primary entity counts must remain unchanged.

### CFIHOS routing boundary
CFIHOS remains on the seven specialist browse implementations during RDL-035.2. The enriched projection is a parity prerequisite, not the route cutover itself.

### Browser validation
GitHub Chromium must prove:
- Water and CCUS still use the shared browser across seven primary entity types
- Unit metadata can be searched through the normalized projection
- Unit dimension filtering is exposed through the generic facet UI
- accessibility remains free of serious/critical violations

Local Playwright remains intentionally excluded on the corporate-managed Mac.

### Next increment
**RDL-035.3 — CFIHOS Shared Browse Cutover**

Only after RDL-035.2 is green:
- route CFIHOS seven primary browse families through `RdlReleaseAwareBrowse`
- preserve explicit `cfihos-2.0` identity
- prove metadata/filter parity in GitHub Chromium
- retire only the specialist browse page implementations/CSS that become unreachable
- retain CFIHOS repositories still used by CIS, Assistant, diagnostics and other product capabilities

### Non-goals
- no CFIHOS route cutover in RDL-035.2
- no CFIHOS repository removal
- no detail-rendering changes
- no hierarchy inference
- no release-status branching
- no relationship-index regeneration
- no local Playwright

## RDL-035.3 — CFIHOS Shared Browse Convergence

### Objective
Route CFIHOS 2.0 through the same `RdlReleaseAwareBrowse` implementation already used by Water / Desalination and CCUS for the seven primary browse families.

### Cutover
The shared browse boundary now takes precedence for:
- Tag Classes
- Equipment Classes
- Document Types
- Properties / Data Dictionary
- Source Standards
- Disciplines
- Units of Measure

CFIHOS uses the explicit `cfihos-2.0` release and the same source-neutral search, hierarchy, metadata and facet contracts as the other RDL sources.

### All-scope behavior
Browse pages require one explicit source/release context. When the global scope is `all`, the browse guard now fails closed with a source-selection message rather than silently rendering CFIHOS specialist content. Cross-source discovery remains available through global search.

### Parity preservation
RDL-035.2 metadata remains the parity layer:
- class parent/synonym search and Abstract badges
- document short code/classification/aliases
- property datatype/dimension/picklist metadata
- discipline code
- Unit symbol/UNECE/dimension/system metadata and dimension facet

The generic browser still contains no CFIHOS repository/model dependency or source-key branch.

### Hierarchy
No hierarchy behavior changed. Tag and Equipment hierarchy remains derived only from authoritative same-release `entity_parent` relationships. All other primary CFIHOS browse vocabularies remain flat.

### Deferred cleanup
The seven specialist CFIHOS browse implementations remain in the codebase but are unreachable from the normal CFIHOS primary browse routes. They are retained for one increment as a comparison baseline while GitHub Chromium proves route, metadata, facet and accessibility parity.
