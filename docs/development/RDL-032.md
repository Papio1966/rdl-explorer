# RDL-032 — Unified Entity Detail Parity and Legacy Convergence

## Objective

Converge RDL Explorer on one release-aware entity-detail architecture without losing capabilities already available in the CFIHOS specialist detail pages.

## RDL-032.1 — parity inspection

The inspection confirmed that RDL-031 established a release/package-isolated generic detail route and static relationship index, while the existing CFIHOS specialist pages still expose additional structured semantics: effective inherited properties, measurement units, controlled values, discipline/document context, reverse class usage and detailed Source Standard mappings.

## RDL-032.2 — parity foundation

This increment extended the static browser projection before any legacy-route ownership changes.

Delivered foundations:

- effective class properties calculated from explicit same-release hierarchy edges, with closest/direct assignments overriding inherited duplicates;
- Property → Unit of Measure projection from explicit workbook unit/dimension identifiers and explicit class-property unit references;
- Property → Controlled Value projection using explicit picklist identifiers without introducing synthetic controlled-list search entities;
- Controlled Value → Source Standard provenance;
- source mapping evidence projected as class/property/standard relationships using explicit workbook identifiers;
- enriched Discipline ↔ Document Type relationship attributes for lifecycle/delivery context;
- richer Information Requirement relationship attributes where the source workbook supplies them;
- reverse projections for Used by Classes, Required by Classes, Document Types and Source Standard usage;
- contextual generic section labels for Tag and Equipment Classes;
- accessible progressive disclosure with `aria-expanded` and `aria-controls`;
- no arbitrary three-field truncation of relationship metadata.

## RDL-032.3 — legacy route convergence

The generic detail renderer is now the canonical active detail surface for CFIHOS entities.

The following compatibility URLs remain supported but redirect immediately to explicit CFIHOS 2.0 generic routes:

- `/classes/tag/:tagClassId` → `/rdl/cfihos/cfihos-2.0/tag_class/:tagClassId`
- `/classes/equipment/:equipmentClassId` → `/rdl/cfihos/cfihos-2.0/equipment_class/:equipmentClassId`
- `/dictionary/:propertyId` → `/rdl/cfihos/cfihos-2.0/property/:propertyId`
- `/documents/:documentTypeId` → `/rdl/cfihos/cfihos-2.0/document_type/:documentTypeId`
- `/disciplines/:disciplineId` → `/rdl/cfihos/cfihos-2.0/discipline/:disciplineId`
- `/units/:unitId` → `/rdl/cfihos/cfihos-2.0/unit_of_measure/:unitId`
- `/standards/:sourceStandardId` → `/rdl/cfihos/cfihos-2.0/source_standard/:sourceStandardId`

The compatibility redirect pins both `cfihos` and `cfihos-2.0`. It does not call `getDefaultReleaseKey` and therefore cannot silently move old URLs to a future default release. Query strings are retained so caller/browse context is not discarded. The redirect uses browser-history replacement so an intermediate compatibility URL does not remain in the Back stack.

The list/browse routes remain unchanged and continue to use the specialist browsing experiences. RDL-032.3 changes active detail ownership only; it does not remove the specialist page source code yet. This keeps the convergence increment small and reversible while ensuring there is only one active detail renderer.

## Release-safety rule

Every generated relationship must resolve both endpoints inside the exact `sourceKey + releaseKey + packageKey` represented in the committed search index. Generation fails closed if an endpoint is absent. No relationship is inferred across releases or packages.

Legacy detail compatibility has a separate release-safety rule: old CFIHOS URLs resolve only to the reviewed `cfihos-2.0` release and never to a mutable source default.

## Search and relationship index stability

RDL-032.3 is routing-only. It does not regenerate or modify `public/rdl-search-index.json` or `public/rdl-relationship-index.json`.

## Validation

Local mandatory gates:

1. RDL-030 release-isolation contract;
2. RDL-031 rich-navigation contract;
3. aggregate RDL-032 parity + legacy-convergence contract;
4. full deterministic regression suite;
5. production build;
6. `git diff --check`;
7. verify both committed runtime index artifacts remain byte-identical.

Playwright is not a local corporate-machine gate. GitHub Actions Chromium remains authoritative for browser E2E and accessibility.
