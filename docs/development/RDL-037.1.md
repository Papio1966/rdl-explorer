# RDL-037.1 — Global Search Runtime Convergence

## Objective

Move the generic Global Search read path onto the PostgreSQL-backed runtime API in production while preserving the exact RDL-030/RDL-035 search semantics, release isolation and explicit JSON rollback/reference mode.

RDL-037.1 is intentionally limited to Global Search. Canonical entity detail remains on its current JSON projection until RDL-037.2.

## Baseline

- Branch: `feature/rdl-037-runtime-read-convergence`
- Baseline merge: `1d46085f010d9060fa8e4f672f57a5aa014ec246`
- RDL-036 is complete.
- Shared browse production authority is already `Browser -> /api/rdl-runtime/* -> PostgreSQL`.
- Global Search and canonical detail are still JSON-backed at this baseline.

## Runtime contract

### Production

```text
Global Search page
    -> runtimeSearch boundary
    -> /api/rdl-runtime/search
    -> RdlRuntimeReadService
    -> RdlRuntimeProjectionRepository
    -> PostgreSQL
```

### Development / current GitHub Vite E2E

The safe default remains explicit `json` because the plain Vite development server does not host the serverless API.

### Explicit modes

- `api` — PostgreSQL runtime API is authoritative.
- `dual` — JSON and API results are compared exactly; API results render only after parity.
- `json` — explicit rollback/reference mode.

API failure in `api` mode fails closed. There is no silent JSON fallback.

## Search semantics preserved

The existing browser search contract is retained exactly:

- whitespace-separated terms are ANDed;
- native identifier, name, definition, entity type, aliases, search text, labels, badges and facets are searchable;
- exact identifier/name and prefix/alias matches retain the established scoring weights;
- result ordering remains score, then name, then source;
- maximum displayed result count remains 80;
- explicit source/release search remains release-isolated;
- `source=all` means the configured default/current release for each source, never every historical release.

The runtime API service now uses the same deterministic ranking semantics whenever `q` is supplied. Queries without `q` preserve the existing RDL-036.2 projection order and pagination used by shared browse.

## All-current strategy

The browser already owns the configured current/default release catalogue. For `source=all`, it sends one explicit source+release query per configured source and asks each release only for its ranked top 80 candidates. The candidates are then re-ranked with the existing browser algorithm to produce the global top 80.

This keeps the API source-neutral and avoids introducing a second server-side definition of "current release".

## Scope boundaries

RDL-037.1 does not:

- modify PostgreSQL schema;
- change relationship APIs;
- change shared browse authority;
- cut over canonical entity detail;
- cut over CIS Builder or Assistant;
- change specialist diagnostic views;
- alter the committed JSON oracle files.

## Acceptance gates

1. Runtime API ranking equals the committed browser search oracle for representative current and historical releases.
2. All-current API results equal the existing JSON global-search top 80.
3. All-current mode queries exactly one configured default/current release per source.
4. Explicit historical release search remains isolated.
5. Dual mode compares exact result records and fails closed on mismatch.
6. API-authority mode fails closed on API unavailability without JSON substitution.
7. Explicit JSON rollback mode makes no API call.
8. RDL-036.2 generic runtime API contract remains green.
9. RDL-030 release-isolated search contract remains green.
10. Application regression and production build pass.
11. Browser oracle hashes remain unchanged.
12. No local Playwright is required; GitHub Actions Chromium remains authoritative.
