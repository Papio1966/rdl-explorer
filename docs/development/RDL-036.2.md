# RDL-036.2 — Generic Runtime Read API

## Objective

Expose the source-neutral PostgreSQL runtime projection proven in RDL-036.1 through a small same-origin read-only API without changing the active browser runtime.

RDL-036.2 creates this boundary:

```text
Browser (unchanged JSON runtime)

Future runtime path prepared by this increment:
Browser -> same-origin API -> RdlRuntimeReadService
                         -> RdlRuntimeProjectionRepository
                         -> PgJsonClient
                         -> PostgreSQL
```

The browser continues to load the committed `public/rdl-search-index.json` and `public/rdl-relationship-index.json` oracles. Browser cutover is deferred to later RDL-036 increments.

## API contract

### `GET /api/rdl-runtime/search`

Required query parameters:

- `sourceKey`
- `releaseKey`

Optional query parameters:

- `entityType`
- `q`
- `offset`
- `limit`

Response schema: `rdl-runtime-search/v1`.

### `GET /api/rdl-runtime/relationships`

Required query parameters:

- `sourceKey`
- `releaseKey`

Optional query parameters:

- `relationshipType`
- `sourceEntityType`
- `sourceNativeIdentifier`
- `targetEntityType`
- `targetNativeIdentifier`
- `offset`
- `limit`

Response schema: `rdl-runtime-relationships/v1`.

## Pagination

- default page size: 100
- maximum page size: 500
- offset must be a non-negative integer
- response returns `total`, `offset`, `limit`, `hasMore`, and `items`

The API paginates the already deterministic RDL-036.1 projection. It does not change projection ordering.

## Release identity

Every request is explicitly scoped by:

```text
sourceKey + releaseKey
```

The service resolves the latest validated package **inside that exact release only**. It never substitutes another release and never interprets an unknown release as "latest".

Unknown explicit source/release combinations return HTTP 404.

Missing or invalid input returns HTTP 400.

Non-GET methods return HTTP 405.

Database runtime failures return HTTP 503 without exposing database connection details.

## Public/runtime boundary

This API exposes the same industry/reference browse projection already distributed through public JSON. It therefore does not introduce governance identity requirements in this increment.

PostgreSQL remains server-only. The API uses the existing pooled `getRdlDatabaseClient()` runtime and the existing request-context/metrics/logging convention in `api/_runtime.ts`.

Every response receives:

- `X-Request-ID`
- `Cache-Control: no-store`

through the shared API runtime boundary.

## Performance boundary

RDL-036.2 adds two additive repository methods:

- `projectSearchRecords(sourceKey, releaseKey)` — reads only entity data required for search projection.
- `projectRelationshipRecords(sourceKey, releaseKey)` — reads entities plus relationships required for relationship projection.

The established RDL-036.1 `project()` implementation is not refactored. This preserves its accepted behavior while preventing a search request from loading the complete relationship graph.

Relationship projection still computes the complete selected release graph before API pagination because some browser relationships are derived from normalized entity/relationship evidence. SQL-level relationship projection optimization is not required for RDL-036.2 and must not change semantics without a separate parity gate.

## Requirements

- **RDL-0362-API-001 — Server-only PostgreSQL** — Browser code shall never receive PostgreSQL credentials or direct database access.
- **RDL-0362-API-002 — Exact source/release scope** — Every runtime read shall require an explicit `sourceKey` and `releaseKey`.
- **RDL-0362-API-003 — No implicit latest** — An unknown explicit release shall fail closed and shall never be replaced by a current/default release.
- **RDL-0362-API-004 — Search projection** — The API shall expose the RDL-036.1 search projection with deterministic filtering and pagination.
- **RDL-0362-API-005 — Relationship projection** — The API shall expose the RDL-036.1 relationship projection with deterministic filtering and pagination.
- **RDL-0362-API-006 — Bounded responses** — Page size shall default to 100 and shall not exceed 500.
- **RDL-0362-API-007 — Source neutrality** — API/service code shall contain no CFIHOS fallback or source-specific routing logic.
- **RDL-0362-API-008 — Operational convention** — Requests shall use the established request correlation, metrics and structured logging boundary.
- **RDL-0362-API-009 — Controlled errors** — Invalid input, unknown releases, unsupported methods and database failures shall return controlled HTTP responses without leaking connection details.
- **RDL-0362-API-010 — No browser cutover** — Existing browser JSON reads remain active.
- **RDL-0362-API-011 — No schema migration** — This increment introduces no PostgreSQL schema change.
- **RDL-0362-API-012 — Focused compatibility** — Additive projection-specific methods shall equal the established RDL-036.1 projection for a complete governed reference release.

## Explicitly out of scope

- browser dual read;
- browser PostgreSQL cutover;
- global all-source/default-release resolution;
- CIS Builder runtime cutover;
- Assistant retrieval cutover;
- specialist diagnostic pages;
- schema migration;
- DataGate integration changes;
- SQL-level optimization that changes projection semantics.

## Acceptance

RDL-036.2 is complete when:

1. both API endpoints return deterministic exact-release pages from PostgreSQL;
2. CFIHOS, CCUS and Water / Desalination are proven through the same source-neutral search endpoint;
3. representative relationship output matches the committed browser relationship oracle;
4. unknown explicit releases fail with 404 and cannot fall back to another release;
5. pagination limits fail closed above 500;
6. the additive projection methods equal the established 036.1 projection on Water / Desalination 2.0 candidate;
7. browser search/detail source files remain JSON-backed;
8. regression and production build pass;
9. the two browser oracle hashes remain unchanged;
10. the exact RDL-036.2 changed-file set is preserved;
11. no local Playwright is required; GitHub Actions Chromium remains the authoritative E2E/accessibility gate.
